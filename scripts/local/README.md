# Owned Windows Sandbox app flow

The full production app-flow script supports CI as before, or explicit `GRAMMAR_OWNED_SANDBOX_TEST=1` in an owned Sandbox. It requires Windows, WDAGUtilityAccount, a different machine from host-machine.txt, fixed guest paths, a Medium integrity token, and a packaged app hash matching its installed MANIFEST. It records the package source commit separately from the test script SHA-256. No synthetic GitHub variables are used. Clipboard and foreground operations are confined to the guest.

The initial local trial ran at High integrity without the debugging port. The b0814c0 packaged app exposed loopback CDP at Medium integrity without policy, firewall, UAC, browser security or app changes. Elevation as the cause is a supported inference, not a completed same-binary High/Medium controlled experiment; the optional High control was blocked by tool approval policy and not executed. Reference: https://github.com/MicrosoftEdge/WebView2Feedback/issues/5645 (Microsoft maintainer explanation of elevated-host hardening). This is an isolated test setup, not proof of ordinary user installation.

Prepare a read-only C:\GrammarPayload mapping containing a receipt-verified `package-flow`, portable `pwsh`, `node.exe`, locked Playwright, `host-machine.txt`, `scripts/test-app-flow-e2e.mjs`, and `test-runtime/NativeEditor.exe` plus `child.exe`. The editor must be compiled from the C# block in `src-tauri/tests/native_edit_harness.ps1` (STA entry calling NativeEditHarness.Run); the child is the existing synthetic Provider fixture, never a real CLI. Keep source and executable hashes in external evidence. Copy `Guest-App-Flow.ps1` to the payload root. Do not map a user profile or credentials. Map a fresh task-owned writable directory to C:\GrammarOutput. Disable networking, clipboard redirection, audio/video/printer redirection, retain ProtectedClient.

Compile `MediumLaunch.cs` using the installed .NET Framework csc into the payload. Run it only in that owned guest with argument `C:\GrammarPayload\Guest-App-Flow.ps1`. It takes a restricted version of its own account token, disables administrator privileges, sets Medium integrity, and assigns user/system access only to the new process's default object ACL. It does not modify account membership, machine policy, or existing files' ACLs. User identity never changes. Its guard rejects host execution. The initial helper without the user default DACL failed DLL initialization; that diagnostic is preserved outside the repository.

The runner selects existing guest WebView2 binaries by explicit process environment, uses the production installer, and executes the same app-flow assertions as CI plus delayed capture-ended regression. It waits at most ten minutes for the owned driver, preserves logs/failure JSON, and uninstalls guest data in finally. The host must inspect both app-result.json and medium-result.json, inspect uninstall.json, stop its own Sandbox, and verify an empty inventory. A helper launch success is not test success. VM startup and foreground failures remain separate from product failures. Live Provider, physical IME, ordinary profile and general installation remain unqualified.

No supplementary CRT, machine-wide runtime install, HKLM debugging policy, execution-policy bypass, or browser sandbox disabling is used.

It verifies the saved safety settings before writing READY_AWAITING_OWNER_INPUT. The guide writes GUIDE_SHOWN separately; verify both receipts before directing the user to interact.

The user physically selects/types/copies/pastes only in the synthetic editor. No input text, clipboard contents or keystrokes are recorded by these scripts; status records remain NOT_RUN until user observations are separately provided. An empty guest language list is unknown availability, not successful Korean IME verification. If unavailable, do not install input features or use synthetic composition events as a substitute for this trial.

The session waits at most 60 minutes, or until `finish.request` appears in its task-owned output directory, then stops only its owned child process trees and runs production uninstall. Closing the Sandbox discards the guest but may prevent an uninstall receipt, so record that distinction. The host must preserve initial preparation failures and current Sandbox ID. This interactive session is intentionally left open for user input; it does not imply autonomous testing or background continuation by the agent.
