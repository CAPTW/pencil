# Grammar Chromium candidate

This candidate implements local Instant assistance for an explicitly enabled current document and non-sensitive field. It is not whole-product acceptance. The Deep path has synthetic native-host and isolated Chromium qualification; real Provider inference is NOT_RUN. Native desktop capture now reads only standard Windows Edit controls (owned synthetic desktop qualification). Desktop (native) Apply never changes text in another application's editor: it is Copy-only for every native editor (review findings R1/R2). This extension still replaces text in an explicitly enabled field on explicit Accept or Apply edit, with reread.

Supported candidate fields: plain textarea and simple `contenteditable="true"` containing at most16 text nodes (or the single bare `<br>` with optional zero-length text nodes Chromium uses for an empty field), in the top document. Rich editors, frames, shadow roots, hidden/readonly/password/sensitive fields and oversized documents are unavailable. Field labels/metadata are a conservative guard, not a promise to identify every semantic secret; enable only non-sensitive writing fields. No automatic text mutation or background cloud analysis occurs.

The extension action enables one current document. Select a supported field and click **Enable this field**. The adjacent annotation card shows precomputed suggestions. Accept and Apply edit recheck the current source/range and reread content; Dismiss/Ignore do not edit. Copy uses an explicit click, with select-and-Ctrl+C fallback if browser clipboard access is unavailable. Pause clears the field cache; Disable document or Alt+Shift+G disables it. The popup offers a domain block and emergency disable. Changing a domain block revokes all current and pending document grants; explicitly enable documents again after the change completes. Concurrent policy changes are rejected as busy. Navigation requires fresh document opt-in. The default package has no native host configured.

Native browser undo is not guaranteed for these DOM replacements. Chromium protocol composition tests cover both supported editors, unchanged composition and a delayed native Instant response; physical Windows IME/caret/device/zoom/long-session behavior and production toolbar activeTab permission still require qualification. Complex controlled editors may override input; a mismatched reread produces an error without retry. The card can overlap other wide elements. Use Hide Grammar panel or Escape inside its controls to release page access; the visible Show panel button restores the cached draft. Hiding does not pause monitoring: use Pause field, Disable document, or Alt+Shift+G to stop. Source changes and cache expiry still invalidate Apply while hidden. The panel repositions on viewport resize and page scroll without reading text or repeating analysis; synthetic320x240 and1280x720 viewports are tested. Extremely small viewports, physical zoom/device and mobile visual viewport behavior remain unqualified. Do not treat a synthetic success as support for an arbitrary website.

## Reproduce the isolated test

Use PowerShell7, Node, Rust and the repository lockfiles. From the mission worktree:

```powershell
npm ci --offline --ignore-scripts
cargo build --manifest-path src-tauri/Cargo.toml --locked --offline --bin grammar-chromium-host
node adapters/chromium/tests/core.test.mjs
node adapters/chromium/tests/worker.test.mjs
$env:GRAMMAR_PLAYWRIGHT = '<installed playwright package directory>'
$env:GRAMMAR_CHROMIUM = '<matching Chromium chrome.exe>'
$env:GRAMMAR_EVIDENCE = '<owned external evidence directory>'
node adapters/chromium/tests/browser.test.mjs
```

For a source-linked extracted candidate, set `GRAMMAR_HOST_EXE` to its host executable and `GRAMMAR_EXTENSION_DIR` to its extension directory before running the same harness. Deep tests additionally require `GRAMMAR_SYNTHETIC_DEEP=1`, the exact task-owned synthetic Claude executable, `P01_FIXTURE_MODE=success`, and a fresh `P01_CASE_DIR` under an evidence `resume-rN` directory. The harness creates that fresh directory before running the fixture. These are fixture-only instructions, not instructions for real Provider inference.

The browser harness creates its own profile, extension copy and synthetic localhost server (port18437). By default only that copied test extension receives the localhost host permission; production uses activeTab. `GRAMMAR_ACTIVE_TAB=1` is a separate diagnostic with production permissions. On the tested Chromium, the protocol action is denied (Method not allowed), so toolbar acceptance remains unqualified; no security/debugging switch was added. It registers a unique current-user native host and removes only that registration in `finally`, keeping evidence files. No existing browser profile, clipboard, account or document is used. Do not run against a port already owned by another process. The test emits content-free counts and synthetic result receipts, not screenshots.

`browser.test.mjs` is therefore a modified isolated extension fixture, even when CI points it at the installed package: it copies the extension, replaces its key/ID, adds the fixture origin permission, rewrites `host-config.js` and registers its own copy of the host. Its receipt says so (`MODIFIED_ISOLATED_EXTENSION_FIXTURE`).

`tests/installed-package.test.mjs` is the installed-package smoke test (CI only, owned desktop). It loads the installed extension directory unmodified: package key/ID, installed permissions and the installer-written `host-config.js`, with the installer's host registration, in a fresh task-owned profile with the browser sandbox on. It verifies those files and the registration first. Page access comes only from the real toolbar. `tests/ui-gesture.ps1` locates the extension's toolbar button (or the Extensions menu and its item) and the popup's Enable button through UI Automation, and clicks them with OS mouse input after a hit test. UI Automation Invoke is used only if a mouse click is covered or has no effect, and Playwright's trusted input on the popup only if UI Automation cannot reach its content. Every such fallback is recorded. It then runs textarea and simple contenteditable analysis in the installed host process, suggestion, explicit Accept/Apply edit and reread. It checks the Disable, cross-origin revocation, second-gesture and reload boundaries, the storage contents, and cleanup (browser, installed host process, profile, unchanged installed files). Worker evaluation only observes page access and storage. The result is NOT_RUN, with the cause, only when UI Automation cannot see the browser window at all; any other missing button, item or popup is a FAIL.

For manual installation, `host/Prepare-Host.ps1` can prepare a fresh directory using a built executable and exact extension ID. It does not register unless `-Register` is explicitly supplied. Its receipt contains a unique host name; set that value in the prepared extension's `host-config.js` and reload it. `Remove-Registration.ps1` checks the exact owned manifest path before removal. Normal-profile installation remains outside this mission's executed actions; no such installation was performed.

## Resource and trust contract

8192 UTF-16 units/document;64 suggestions;60s cache TTL;250ms debounce;four active or retiring documents;one native request/document;5s Instant response timeout;128KiB native input frame. Text and suggestions stay in process memory. Non-content denied-origin preferences and opaque unfinished-Deep markers persist. Host framing/origin/operation validation has no arbitrary shell/path execution. Hover/card focus does not invoke analysis. A service-worker restart loses permission and requires an explicit enable. An unfinished marker blocks new Deep work. The popup **Check completed cleanup** action queries the installation-owned native receipt without sending any document text or invoking a Provider. It releases only exact checked-complete work or an unstarted reservation atomically retired before any later admission. Consent is never restored by recovery. Local Instant remains available. Never clear a marker as proof that its process cleanup completed. Four fixed receipt slots hold only opaque installation/token/generation/state. The worker persists reservation intent before contacting the host and persists acknowledgment intent before freeing a slot. A lost reservation reply can be found by its token. A hard-crash PENDING, an intent with no native record, legacy markers, or missing/corrupt storage remains blocked; Local Instant remains available. Origin-only older host installations are Instant-only. These limits are deliberate: PID absence or elapsed time is not cleanup proof. The receipt store is Windows-only; power-loss durability and malicious same-account file modification are not qualified.

The host uses the existing Rust Instant engine and shared Provider executor. Deep requires popup consent for one selected Provider and a separate explicit Send action for the current enabled field. The disclosure covers the whole current field, with no terminology transmitted. The result is cached for review; only Accept/Apply edit mutates after exact epoch/revision/source checks. Editing the field, revoking consent, pausing or navigation cancels the request. The host receives cancellation/EOF concurrently and awaits actual cleanup. The browser allows120s for Deep and5s for its cancellation receipt; failure retains a blocked owner, never a silent retry/fallback.

Provider choices remain codex, antigravity and claude. Chromium Antigravity currently returns `provider_privacy_unqualified` before probing because history suppression has not been qualified. Claude requests carry no-session-persistence, bare discovery isolation and all-tools denial. Installed Claude2.1.282 recognizes these options, but bare mode does not use OAuth/keychain authentication. Existing OAuth sign-in is therefore insufficient for this candidate's Claude writing path; no credential setup or paid request is authorized by the synthetic test instructions. This restriction also affects the shared desktop Claude path. Codex uses its existing ephemeral/history-disabled request path. No real Provider inference was executed. The default host configuration remains unset.

Claude argument semantics are documented in the [official CLI reference](https://code.claude.com/docs/en/cli-reference). Synthetic tests can establish that the flags reach the process; they cannot establish a real Provider's retention behavior.
